§1 — Σύντομη παρουσίαση / Στόχος

Καλησπέρα. Είμαστε η ομάδα 7. Τα μέλη: Εκατομμάτη Ελευθερία, Καλλιγεράκη Αλεξάνδρα, Κουτσοχρήστου Ελευθερία και Σταμέλος Αθανάσιος.

Το project μας είναι μια διαδικτυακή πλατφόρμα μεσιτικού γραφείου — ιδιοκτήτες και μεσιτικά γραφεία δημοσιεύουν αγγελίες ακινήτων, και οι ενδιαφερόμενοι αναζητούν, επικοινωνούν και αξιολογούν. Η ανάπτυξη βασίζεται στη μεθοδολογία RUP με πλήρη UML documentation.

30''Μεθοδολογία RUP — 3 φάσεις υλοποίησης
§ RUP — Inception / Elaboration / Construction

Χρησιμοποιήσαμε RUP — Rational Unified Process. Τρεις φάσεις: Inception (απαιτήσεις + πρώτα διαγράμματα), Elaboration (πλήρης σχεδιασμός + 1η εκτελέσιμη), Construction (τελικά διαγράμματα + παραγωγική εφαρμογή). Κάθε φάση παράγει παραδοτέα διαγραμμάτων και κώδικα.

Φάση Inception — Απαιτήσεις + 1η έκδοση διαγραμμάτων
35''Απαιτήσεις συστήματος & Actors
Λειτουργικές απαιτήσεις Μη-λειτουργικές απαιτήσεις Actors: User / Customer / Agency / Owner / Admin

Λειτουργικές απαιτήσεις: Διαχείριση αγγελιών ακινήτων προς πώληση ή ενοικίαση, Διαγραφή αγγελίας, Αναζήτηση ακινήτων, Αξιολόγηση αγγελίας. Μη-λειτουργικές: ασφάλεια, επεκτασιμότητα, usability.

Τέσσερις τύποι χρηστών: Customer (αναζητά ακίνητα), Owner (ιδιοκτήτης), Agency (μεσιτικό γραφείο), Admin (διαχειριστής).

50''Use Case Diagram — 1η έκδοση · 12 UCs
Εικόνα: Διάγραμμα περιπτώσεων χρήσης (1η έκδοση)

Το πρώτο Use Case Diagram ορίζει 12 περιπτώσεις χρήσης: UC-01 Εγγραφή, UC-02 Σύνδεση, UC-03 Αναζήτηση ακινήτου, UC-04 Προβολή αγγελίας, UC-05 Δημιουργία αγγελίας, UC-06 Επεξεργασία, UC-07 Διαγραφή, UC-08 Αποστολή μηνύματος, UC-09 Αξιολόγηση, UC-10 Έγκριση/Απόρριψη από Admin, UC-11 Διαχείριση χρηστών, UC-12 Αναφορά αγγελίας.

Το διάγραμμα δείχνει ποιος actor έχει πρόσβαση σε ποια λειτουργία.

50''Class Diagram — 1η έκδοση
Εικόνα: Διάγραμμα τάξεων (1η έκδοση) Σχέσεις μεταξύ κλάσεων

Η πρώτη έκδοση αποτυπώνει τη βασική δομή: κλάσεις User, Owner, Agency, Customer, Admin — με κληρονομικότητα από User. Κλάσεις Listing, Property, Message, SearchFilter.

Σχέσεις: Owner δίνει 0..* Listings. Listing έχει 0..* Properties. SearchFilter φιλτράρει Listings. Αυτή η δομή είναι η βάση όλων των επόμενων εκδόσεων.

40''Use Case Diagram — 2η έκδοση · include / extend / generalization
Εικόνα: Διάγραμμα περιπτώσεων χρήσης (2η έκδοση)

Στη 2η έκδοση εμπλουτίζουμε τις σχέσεις. «include»: η Δημιουργία Αγγελίας include-αρει το Login — δεν μπορείς να δημοσιεύσεις χωρίς σύνδεση. «extend»: η Αναζήτηση extend-αρεται από τα Φίλτρα. «generalization» μεταξύ ρόλων χρηστών.

Ξεκαθαρίζεται ποια UCs ανήκουν αποκλειστικά σε Admin, ποια σε Owner/Agency, ποια σε Customer.

1' 10''Αναλυτικά σενάρια: UC-05 Δημιουργία Αγγελίας & UC-10 Έγκριση
UC-05: Δημιουργία αγγελίας — Actors: Owner, Agency UC-10: Έγκριση/Απόρριψη αγγελίας — Actor: Admin

UC-05: Ο Owner/Agency επιλέγει δημιουργία αγγελίας → το σύστημα εμφανίζει φόρμα → συμπληρώνει στοιχεία και υποβάλλει → έλεγχος εγκυρότητας → αποθήκευση στη βάση με κατάσταση PENDING → ειδοποίηση Admin → μήνυμα επιτυχίας. Εναλλακτικό σενάριο: μη έγκυρα στοιχεία → επιστροφή για διόρθωση.

UC-10: Ο Admin μεταβαίνει στη Σελίδα Έγκρισης → επιλέγει αγγελία → ανάκτηση από βάση → έλεγχος → έγκριση (ACTIVE) ή απόρριψη → ενημέρωση κατάστασης → μήνυμα επιτυχίας. Ασφάλεια: καμία αγγελία δεν εμφανίζεται χωρίς Admin έλεγχο.

45''Class Diagram — 2η έκδοση · νέες κλάσεις & enumerations
Εικόνα: Διάγραμμα τάξεων (2η έκδοση) Enum listingStatus · κλάση Rating · κλάση Image

Στη 2η έκδοση το μοντέλο εμπλουτίζεται σημαντικά. Προστέθηκαν: κλάση Rating (αξιολόγηση αγγελίας από Customer), κλάση Image (φωτογραφίες ακινήτου).

Νέες σχέσεις: Listing έχει List<Image> και List<Rating>. Αυτό είναι το θεμέλιο για τη 3η έκδοση που θα δούμε στην Construction.

55''Object Diagram — 1η έκδοση & Collaboration Diagrams (×3)
Εικόνα: Διάγραμμα αντικειμένων (1η έκδοση) Εικόνα: Διάγραμμα συνεργασίας – δημιουργία αγγελίας (1η έκδοση) Εικόνα: Διάγραμμα συνεργασίας – αναζήτηση ακινήτου (1η έκδοση) Εικόνα: Διάγραμμα συνεργασίας – αποστολή μηνύματος (1η έκδοση)

Το Object Diagram δείχνει ένα συγκεκριμένο στιγμιότυπο — μια αγγελία με τιμές πεδίων, συνδεδεμένη με τον Owner της. Σε αντίθεση με το Class Diagram που είναι γενικό, εδώ βλέπουμε πραγματικά δεδομένα.

Τα Collaboration Diagrams δείχνουν τη συνεργασία αντικειμένων σε 3 σενάρια: (1) δημιουργία αγγελίας — Form → Redux action → store, (2) αναζήτηση — SearchFilter → DB → αποτελέσματα, (3) αποστολή μηνύματος — Customer → Message → Owner notification.

50''Sequence Diagrams — 1η έκδοση (×4 σενάρια)
Εικόνα: Διάγραμμα σειράς – δημιουργία αγγελίας (1η έκδοση) Εικόνα: Διάγραμμα σειράς – αναζήτηση ακινήτου (1η έκδοση) Εικόνα: Διάγραμμα σειράς – αποστολή μηνύματος (1η έκδοση) Εικόνα: Διάγραμμα σειράς – έγκριση αγγελίας από Admin (1η έκδοση)

Τα Sequence Diagrams δείχνουν τη χρονική ακολουθία μηνυμάτων μεταξύ αντικειμένων. Έχουμε 4 σενάρια. Το πιο χαρακτηριστικό: Έγκριση από Admin — ο Admin επιλέγει αγγελία → σύστημα ανακτά από βάση → εμφανίζει για έλεγχο → Admin εγκρίνει → ενημερώνεται η κατάσταση → μήνυμα επιτυχίας. Η ακολουθία αποδεικνύει ότι καμία αγγελία δεν γίνεται ACTIVE χωρίς ρητή έγκριση.

35''Activity Diagrams — 1η έκδοση (×4 ροές)
Εικόνα: Διάγραμμα δραστηριοτήτων – δημιουργία αγγελίας (1η έκδοση) Εικόνα: Διάγραμμα δραστηριοτήτων – αναζήτηση ακινήτου (1η έκδοση) Εικόνα: Διάγραμμα δραστηριοτήτων – αποστολή μηνύματος (1η έκδοση) Εικόνα: Διάγραμμα δραστηριοτήτων – έγκριση αγγελίας (1η έκδοση)

Τέσσερα Activity Diagrams για τις βασικές ροές. Εστιάζω στην Αναζήτηση: χρήστης εισάγει φίλτρα → SearchFilter εφαρμόζει κριτήρια → αναζήτηση στη βάση → αποτελέσματα ή μήνυμα «δεν βρέθηκαν ακίνητα». Στην εφαρμογή αυτό γίνεται real-time μέσω Redux selectors.

35''State Machine Diagram — 1η έκδοση · κύκλος ζωής αγγελίας
ΕΙΚΟΝΑ: Διάγραμμα καταστάσεων (1η έκδοση) Καταστάσεις: Draft → Pending → Active → Inactive → Sold/Rented

Το State Machine δείχνει τον κύκλο ζωής μιας αγγελίας: ξεκινά ως Draft, γίνεται Pending μετά υποβολή, Active μετά έγκριση Admin, Inactive αν αποσυρθεί, Sold/Rented όταν ολοκληρωθεί η συναλλαγή. Κάθε μετάβαση αντιστοιχεί 1:1 σε Redux action στο data_listings slice.

30''Component & Deployment Diagrams — 1η έκδοση
ΕΙΚΟΝΑ: Διάγραμμα εξαρτημάτων (1η έκδοση) — Client-Server, REST API ΕΙΚΟΝΑ: Διάγραμμα διανομής (1η έκδοση) — Web Browser → App Server → DB

Η αρχιτεκτονική βασίζεται σε Client-Server. Το Component Diagram δείχνει: Frontend (React, Web Browser) ↔ REST API ↔ 4 υποσυστήματα Backend (User & Auth, Listing Management, Messaging, Search & Filter) ↔ κεντρική βάση δεδομένων. Το Deployment Diagram δείχνει τη φυσική τοποθεσία: browser → application server → database server.

30''Ενημερωμένα διαγράμματα Construction (2η έκδοση δυναμικών)
Εικόνα: Διάγραμμα αντικειμένων (2η έκδοση) — + Image & Rating instances Εικόνα: Διάγραμμα συνεργασίας (2η έκδοση – αξιολόγηση, έγκριση) Εικόνα: Διαγράμματα σειράς (2η έκδοση) ×4 Εικόνα: Διαγράμματα δραστηριοτήτων (2η έκδοση) ×4 Εικόνα: Διάγραμμα καταστάσεων (2η έκδοση) — + Expired / Deleted Εικόνα: Διάγραμμα εξαρτημάτων (2η έκδοση) — + Media Service Εικόνα: Διάγραμμα διανομής (2η έκδοση) — + File Storage node
